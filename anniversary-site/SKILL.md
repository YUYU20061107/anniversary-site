# 纪念日互动网站

这个 skill 带着一套做好并测过的网页模板。你的工作不是从头写网站，而是：问清楚两个人的真实内容 → 复制模板 → 处理照片 → 填配置 → 在真实浏览器里验证 → 交付。

模板是纯静态文件，没有构建步骤，双击 `index.html` 就能打开。

## 模板里有什么

| 页面 id | 内容 | 需要的素材 |
|---|---|---|
| `p-cover` | 夜空、满天星、相机；按快门洗出拍立得，显示在一起的天数 | 照片、日期 |
| `p-film` | 两条可拖动的胶卷，点一格放大 | 照片、每张的小字 |
| `p-board` | 等距 3D 大富翁：两个小人掷骰子走一圈，每 3 格一件两人的大事，路上捡奖励 | 1~6 件事、奖励 |
| `p-table` | 小餐桌：不爱吃的菜点一下撤走，最爱的拿不走 | 爱吃 / 不爱吃的菜 |
| `p-hands` | 一只手举着一张门票，点一下变成两只手两张连座票，背景变演唱会 | 无（日期自动印上） |
| `p-game` | 横版跳跃：开始只有 1P，半路 2P 加入后才有二段跳，翻过一个人过不去的墙 | 无 |
| `p-vinyl` | 唱片机：点一下换唱片，背景音乐从第一首切到第二首 | 两首歌 |
| `p-finale` | 方块和光点飞进来拼成合照，旁边逐句出现一段话 | 一张合照、一段话、落款 |

不需要的页面在配置里用 `hidePages` 关掉即可，不用删代码。

## 流程

### 1. 先问清楚内容

礼物的价值全在"这是我们俩的事"。编出来的细节（她爱吃什么、第一次约会在哪）一旦错了，比留空更糟，所以不知道的就问，不要替人编。

一次性把需要的东西列给用户，让对方能一口气回答：

- **照片文件夹的位置**，以及哪一张做结尾合照（最好是两个人都看镜头的横图）
- **在一起的日期**；纪念的是哪一天（周年当天，还是送礼物那天）
- **封面标题**（比如"我们的第一年"）
- **对方爱吃和不爱吃的东西**（各 2~4 样最合适）
- **两个人的大事**，最多 6 件，按时间顺序（第一次说话、第一次约会、一个约定……）
- **结尾想说的话和落款**
- **音乐**（可选）：一首背景音乐；如果想要唱片机切歌那一页，再要第二首，以及这两首歌对两人的意义
- **大富翁路上的奖励**（可选，比如抱抱券、奶茶一杯）
- 有没有不想要的页面

用户只给了一部分也可以先做，不用等。没给的部分按下面处理，并在交付时**明确列出哪些是你写的、哪些还是示例**：

- **关于对方的事实（菜、大事）**：只放用户说过的，宁可少也不要用示例凑数。4 道菜、2 件事页面都能正常显示。示例里的"香菜""火锅"留在成品里，就等于替用户编了对方的口味。
- **标题**：按周年数顺着改（两周年就是"我们的第二年"），交付时说一声。
- **结尾的信**：示例那封不能原样留下。它写着"一周年快乐"，还提到门票、2P 和游戏的像素，年数不对或对应页面被隐藏时就对不上了。根据用户给的事实写一封简短的草稿，只提成品里真的有的页面，并告诉用户这是草稿，最好换成自己的话。
- **奖励、每道菜的台词、卡片上的小字**：这些是装饰性的，可以保留示例或自己写，交付时说明。

找照片时只看用户指给你的文件夹。不要为了"找找看"去翻对方的图片、下载、桌面等目录，那里会有证件、聊天截图这类与任务无关的隐私。

### 2. 复制模板

把 `assets/template/` 整个复制到用户想放的位置（没说就问，或放在照片文件夹旁边），文件夹名用英文，例如 `our-first-year`。之后所有修改都在这份副本里做。

```bash
cp -r "<skill>/assets/template" "<网站文件夹>"
```

### 3. 处理照片

```bash
python -I <skill>/scripts/prepare_photos.py --photos "<照片文件夹>" --site "<网站文件夹>" --finale <编号或文件名>
```

需要 Pillow（`pip install pillow`）。脚本会：

- 把照片缩小并存成 `photos/p00.jpg`、`photos/t00.jpg`……（原图不动）
- 生成 `js/mosaic-data.js`（结尾合照的马赛克数据）
- 打印每张照片的编号，并生成一张带编号的总览图 `photos/_overview.jpg`

`--finale` 可以写编号，也可以写原文件名（带不带扩展名都行）；不写就用第一张。

**看一眼总览图**（用 Read 打开），然后再写每张照片的小字和挑结尾合照。小字按编号顺序填进 `captions`，条数和照片张数一致。看图写的小字是你的猜测，交付时要说明，让用户改。看不出照片内容、或者拿不准时，那一条写空字符串 `''`（拍立得下面就不显示字），不要留着"示例小字"。

每次增删照片或换结尾合照，都要重新运行这个脚本。HEIC 格式读不了，请用户先转成 JPG。

用户暂时没有照片时，可以用 `--demo` 生成占位图先看效果。

### 4. 填配置

所有内容都在网站文件夹的 `js/config.js` 里，文件里每一项都有注释。几个容易错的地方：

- **日期要自洽。** 封面天数 = `anniversaryDate − startDate`。如果标题写"第一年"、信里写"一周年快乐"，那 `anniversaryDate` 应该正好是一周年那天；否则天数会显示成 411 这种和文案对不上的数字。发现对不上时，把情况告诉用户让他选，不要自己悄悄改。
- **引号和逗号必须是英文半角。** 写完用 `node --check js/config.js` 检查一下语法。
- `journey` 最多 6 件事，按数组顺序出现；给其中一件加 `house: true`，棋盘中间会盖起一座小房子，适合放在"家""未来"这类约定上。
- `dishes` 4~8 道都可以，爱吃和不爱吃的交替排列；至少要有一道不爱吃的，否则这一页没有可点的东西。
- 标题 `title` 太长会在手机上折行，控制在 8 个字以内。

### 5. 音乐（可选）

把音频文件复制到网站文件夹的 `audio/` 下（文件名用英文），然后取消 `config.js` 里 `music` 那一段的注释并填好。

- 只写 `first`：全程一首背景音乐，没有唱片机页。
- `first` + `second`：出现唱片机页，点一下从第一首切到第二首。`label` 是印在唱片中间的短标记（比如歌名 "99" 和 "100"），`before` / `after` 是切歌前后的大字，写这两首歌对两人的意义。

浏览器不允许网页一打开就出声，所以音乐是在第一次点击（比如按相机快门）时开始的。这一点要告诉用户，免得以为坏了。

歌曲文件会让文件夹变大很多（一首 320kbps 的歌约 10 MB）。如果用户打算把网站公开发布到网上而不是私下发给对方，提醒一句有版权的歌不适合公开挂出来。

### 6. 验证

改完不要直接说"做好了"。按这个顺序验证：

```bash
cd "<网站文件夹>"
node --check js/config.js
node --test tests/logic.test.js tests/board.test.js
PLAYWRIGHT_PATH="<装了 playwright-core 的文件夹>/node_modules/playwright-core" node tests/e2e.js
```

`tests/e2e.js` 会用本机的 Edge / Chrome 把每一页真的点一遍（掷骰子走完一圈、撤菜、让机器人打通小游戏、切歌并确认音乐进度在走），在桌面、手机竖屏、手机横屏三种尺寸下截图到 `tests/shots/`。

它需要 `playwright-core`（只是驱动库，不会下载浏览器）。电脑上没有的话，在网站文件夹**之外**找个地方 `npm i playwright-core`，再用上面的 `PLAYWRIGHT_PATH` 指过去；不设这个变量、它又不在网站文件夹里时，脚本会以退出码 2 结束并提示找不到。这是往用户电脑上装东西，装之前先说一声。找不到浏览器时用 `BROWSER_PATH` 指定 Edge 或 Chrome 的完整路径。

跑完后**打开几张截图看**：自动测试只能证明没报错、能点通，证明不了好不好看。重点看封面的拍立得有没有挡住标题、大富翁的事件卡文字有没有溢出、手机上有没有被裁掉的内容。

如果环境里没有 Node 或浏览器，就如实告诉用户哪些没验证，不要说成已经验证过。

### 7. 交付

告诉用户：

- 入口是哪个文件，双击即可
- 哪些内容是用户给的，哪些是你写的或还是示例（小字、每道菜的台词、奖励、卡片上的小字通常是你写的）
- 验证了什么、没验证什么（真手机、Safari、音乐的实际听感通常没法验证）
- 发给对方时要**打包整个文件夹**，只发 `index.html` 会看不到照片、字体和音乐
- 打包前可以删掉 `tests/` 文件夹和 `photos/_overview.jpg`：它们只是制作时用的，对方用不到，截图里还会提前剧透内容
- 以后想改内容只需要改 `js/config.js`

## 想改模板本身

用户想要配置项之外的改动时（换配色、加一页、改小游戏关卡、改小人的衣服），先读 `references/customizing.md`，里面有文件地图、每一页的实现方式和几条改动时容易踩的坑。

保持这几条不变，它们是模板能"双击就开"的前提：

- 不引入构建工具和框架，不用 `fetch`、ES module、需要服务器的东西——`file://` 下都会失败。
- 不从 canvas 读图片像素（`getImageData`）——`file://` 下会被浏览器拦住，所以合照的颜色才要用脚本提前算好。
- 字体、图片都在本地，不依赖 CDN，没网也能打开。
